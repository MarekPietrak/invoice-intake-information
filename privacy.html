Privacy notice

How Invoice Intake Automation handles data in its personal-use, self-managed Gmail-to-Drive workflow.

Last updated 2026-11-10.

In brief

Gmail attachments are processed by a local n8n installation. Eligible document content is sent to the OpenAI API. Accepted original invoices are stored in the account owner’s Google Drive. This public website does not collect or receive those documents.

1. Scope

This notice describes a self-managed automation used by its operator for their own authorized Google account. It is not a public, multi-user invoice-processing service. No public registration, mailbox connection, document-upload form, or subscription is offered on these pages.

The public information website and the private automation are separate. Visiting this website does not connect a Google account or trigger document processing.

2. Google account access

Access is granted using Google OAuth to the credential configured in the operator’s n8n installation. The workflow uses that authorization to retrieve matching Gmail messages and attachments and to look up, create, and verify files or folders in its configured Google Drive archive.

The configured intake checks incoming messages with attachments and excludes sent, draft, spam, and trash messages. Both read and unread messages can be eligible. Google permissions may be broader than these workflow filters; the consent screen shows the actual permissions being requested.

The public website does not receive Google account passwords or OAuth tokens. Credentials are managed in the operator’s n8n installation, not in these static pages.

3. Data processed

  • Message and attachment data: message identifiers, labels and metadata, attachment filenames, MIME types, sizes, and attachment contents. Email content can be present temporarily in the Gmail retrieval response while attachments are obtained.
  • Document content: PDF text or document images, including any names, addresses, business details, invoice numbers, dates, totals, or other information visible in the source document.
  • Derived information: document category, model probabilities, extracted invoice identity and issue date, validation evidence, and processing outcomes.
  • Processing records: attachment hashes, source identifiers, filenames, status notes, supplier and invoice identifiers when extracted, routing month, archive file/folder identifiers, sizes, and timestamps.

Attachment retrieval can temporarily download additional files in the same message. The configured downstream selection sends only supported candidate PDFs and images for document analysis.

4. Purpose and data transfers

Data is used to identify invoice-related documents, extract and validate invoice identity and issue dates, avoid duplicate processing, record outcomes, and archive accepted original documents by issue month.

Local n8n installation

Coordinates retrieval, file checks, native PDF text extraction or private PDF rendering, classification, validation, recordkeeping, and filing. Rendering is performed by the operator’s private rendering service; the public website is not a processing endpoint.

OpenAI API

Supported candidate documents are submitted as extracted text or document images with task instructions for classification. Likely invoices can be submitted for additional field extraction. Visible personal and financial details in those documents can therefore be processed by OpenAI.

The configured model requests do not intentionally include the email body, mailbox history, or unrelated attachments as classification input. This does not remove information already printed inside the submitted document.

OpenAI processing and retention are subject to the API account’s settings and OpenAI’s API data controls. This notice does not promise zero retention or claim that a Zero Data Retention agreement is in place.

Google Gmail and Drive

Google provides the source mailbox and destination archive. The workflow stores accepted original files in the selected Drive location and reads file metadata to verify the upload. Data stored in Google services remains subject to the Google account’s settings and applicable Google privacy policy.

The workflow does not include advertising, data sale, or generalized model-training functions. The disclosed transfer to OpenAI is for the requested document-processing feature, not for an unrelated purpose.

5. Storage and retention

  • Gmail: the original messages remain in the owner’s account unless the owner separately removes them. This workflow is not configured to delete source messages.
  • Google Drive: accepted archived originals remain until the account owner removes them or an applicable account policy acts on them. This workflow does not implement an automatic archive-expiry period.
  • Local processing ledger: metadata, outcomes, and available extracted invoice fields are retained in the n8n data table until the operator removes them. They are not published on this website.
  • Temporary files and execution data: documents, extracted text, and responses can exist in runtime memory, binary storage, or execution storage. The current workflow disables saved successful and failed production execution data but allows saved manual executions. Temporary storage and pruning depend on the n8n installation; immediate deletion is not guaranteed.
  • External providers: provider-side logs, processing records, backups, or other retention depend on the provider’s applicable policies and account settings. A local deletion does not automatically remove provider-held data.

No fixed, universal deletion period is promised for all processing locations.

6. Your control and deletion

The account owner can disable the n8n workflow to stop future automated processing and can revoke the app’s access through Google Account → third-party connections.

Revoking authorization does not delete previously archived invoices, local processing records, saved execution data, or provider-held records. The owner can manage Gmail and Drive data directly in their Google account and remove ledger or execution data in their n8n installation. Provider-held data must be managed using the relevant provider’s controls.

Before enabling this workflow, the operator must be authorized to process any third-party personal data present in the selected messages and documents.

7. This public website

The site code contains no upload or contact forms, advertising, analytics, third-party scripts, remote fonts, cookies, or browser-storage functionality. It does not access a mailbox, call document models, or receive invoice data.

When these pages are hosted on GitHub Pages, GitHub may collect technical request information, including visitor IP addresses, for security purposes, as described in GitHub Pages data collection and the GitHub privacy statement. External policy links are visited only when selected by the visitor.

8. Google API Services and Limited Use

The use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Google user data is to be used only for the described document-processing and archiving features and their operation, not for advertising, sale, or an undisclosed secondary use. Any material change to the data accessed, purpose, or recipients requires updating this notice and obtaining any necessary consent before the changed processing begins.

9. Changes and administration

This is a single-user, self-managed tool. The connected account owner is responsible for the installation, its Google permissions, provider account settings, and data-management decisions. There is no separate public support service or public registration process.

No personal contact details are published on this website. The operator can be reached through a communication channel they choose to provide privately.

This notice must be reviewed when the actual workflow or its providers change. Publishing these pages does not mean Google has reviewed or verified the app.
